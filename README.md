## About

I started in ML — models, experiments, feature engineering. What pulled me deeper was everything *around* the model. How does data get there cleanly? How does the model actually run in production without breaking a week later? How do we build something that works on Monday and still works on Friday?

That's where I've spent most of my time: pipelines, warehouses, CI/CD, APIs. Not just training models but shipping them.

Built a full MLOps system for network threat detection — MongoDB as data lake, automated ETL, XGBoost training with MLflow tracking, FastAPI serving, Dockerized and deployed to AWS EC2 via GitHub Actions. Built a Snowflake warehouse with layered ELT and incremental pipelines. Built an Oracle PL/SQL OLTP system with its own custom unit testing framework. Along the way I also mentored students at Skoolam NGO — turns out explaining a concept clearly is harder than building it.

Currently looking for a full-time role. Open to ML, data engineering, or MLOps.

## Projects

### [Network Security System — MLOps Pipeline](https://github.com/28Deepakpandey/Network-Security-System-MLOps-Project-with-ETL-)
`Python` `FastAPI` `Scikit-learn` `Docker` `GitHub Actions` `AWS` `MLflow` `MongoDB`

Phishing/network threat detection built as a proper production system. 30-feature URL dataset → MongoDB data lake → automated ingestion, schema validation, ETL/preprocessing pipeline → XGBoost model with MLflow experiment tracking → FastAPI `/train` and `/predict` endpoints → Docker image pushed to AWS ECR, deployed to EC2 on every push to main via GitHub Actions. Custom logging and exception handling across all components.

---

### [Sales Analytics Data Warehouse](https://github.com/28Deepakpandey/Snowflake-data-warehouse-for-sales-analytics)
`Snowflake` `SQL` `ELT` `Streams & Tasks` `Data Modeling` `BI`

Layered Snowflake architecture: RAW → STAGING → REPORTING. Incremental ELT pipelines using Snowflake Streams and Tasks, fact/dimension data modeling, Stored Procedures for orchestration. Designed for analytics reliability and data integrity — not just a working query, but a maintainable system.

---

### [Content-Based Recommendation Engine](https://github.com/28Deepakpandey/recommendation-system)
`Python` `TF-IDF` `Cosine Similarity` `NLP` `Streamlit`

Movie recommendation system on TMDB 5000. TF-IDF vectorization + cosine similarity for content matching. Full preprocessing notebook, serialized model artifacts, and a Streamlit app for live recommendations.

---

### [Student Performance Prediction](https://github.com/28Deepakpandey/Student-Academic-Performance-Prediction-System-ML-Project-)
`Python` `Scikit-learn` `EDA` `Supervised Learning`

End-to-end supervised ML pipeline predicting academic outcomes. Data cleaning, EDA, feature engineering, model evaluation.

---

### [Bank Account Management System (OLTP)](https://github.com/28Deepakpandey/PL_SQL-LAB/tree/main/BankAccountManagementSystem)
`Oracle SQL` `PL/SQL` `Stored Procedures` `Triggers` `Unit Testing`

OLTP schema in Oracle PL/SQL — stored procedures, triggers, and functions automating core banking operations with ACID-compliant transactions. Built a custom test framework (utPLSQL-style) for structured PASS/FAIL validation of all database logic.
